# KubeJS 工作台完善方案

> 状态：P1 已在 0.44.0 实现；P2 实例索引、图标、补全与版本模板已在 0.45.0–0.46.0 实现；P3 全部完成：AST 语义预检/问题面板/日志定位在 0.47.0，AI 选区改写 + diff 在 0.48.0，AST 释意升级在 0.48.2；P4 配方生成器在 0.49.0，图标与大网格/自定义 JSON 在 0.50.0，机器/祭坛可视化在 0.51.0，标签生成器在 0.52.0 完成 · 2026-10-30  
> 范围：整合包工坊里的 KubeJS 页；不改模组筛选、服务端包和启动链路  
> 目标版本：0.44.0 起，按阶段独立发布

## 0. 一句话结论

现在的 KubeJS 页只是“能改文件的文本框”；真正卡住整合包作者的是**不知道 ID、不知道写对没、改坏回不去**。  
完善方向不是把它做成通用 IDE，而是做成一个闭环的配方工作台：**写 → 查 → 验 → 回滚**，AI 只做加速器。

## 1. 现状盘点

### 1.1 已有能力

- KubeJS 文件树、读取、新建、保存、删除。
- 保存前 JS/JSON 语法检查；保存/删除前备份到 `backups/kubejs`。
- 7 个固定模板；AI 生成（可选，仅点击时调用）。
- 本地释意 + AI 深释意；释意是逐行正则识别。
- 工坊导出 `.mrpack` 时包含 `kubejs/`。

### 1.2 真正的缺口

| 环节 | 现状 | 作者实际感受 |
| --- | --- | --- |
| 写 | 纯 `<textarea>`，单文件，无行号/高亮/查找/补全 | 写长脚本像在记事本里改配置 |
| 查 | 没有物品、配方、标签索引 | 要开游戏、EMI/REI 或浏览器查 ID，再切回来 |
| 验 | 保存时只查 JS 语法 | 写错 ID、放错脚本目录、标签命名空间不对，只有启动游戏才发现 |
| 回 | 备份在磁盘里，但界面看不到 | 改坏了只能去文件夹里翻时间戳 |
| 释意 | 逐行正则，只认简单的 `remove({id/output/mod})` | 真实脚本里的 `input`、`type`、`Item.of`、多行对象会漏 |
| 布局 | 弹窗内两栏，AI 区挤在编辑器下方 | 右侧没有放知识/问题/释意的地方 |

### 1.3 真实数据探针（只读）

对真实 `miao` 实例（Forge 1.20.1 / KubeJS 2001.6.5）做了一次只读索引探针：

| 项目 | 结果 |
| --- | --- |
| 模组 jar | 308 个 / 0.43 GB |
| zip 条目 | 339,822 |
| 配方 JSON | 33,188（33,176 可解析） |
| 物品模型 | 27,864 |
| 语言文件 | 395（`zh_cn` / `en_us`） |
| 命名空间 | 140 |
| 首次扫描耗时 | 12.4 s（Node + adm-zip，未缓存） |
| 峰值 RSS | 766 MB（朴素实现，保留了全部 zip entry） |
| 读取失败 | 0 |

结论：**索引在启动器里完全做得到**，3.3 万条配方足够覆盖绝大多数“删配方/加配方/查 ID”的需求；但实现必须逐 jar 释放引用、只保留紧凑投影，不能把上面的 766 MB 直接搬进应用。

KubeJS 目录本身也有典型形态：93 个文件、3 个脚本目录（外加 `data/`、`assets/`、`config/`）、`craft custom/` 这种带空格的多级目录、24 KB 的单脚本、`forge:` 标签、`Item.of(...)` 和 `input`/`type` 选择器。当前释意和模板都没有覆盖这些。

## 2. 目标与非目标

### 目标

把 KubeJS 页变成一个**不离开启动器就能完成大部分配方魔改**的工作台：

1. **写得顺**：高亮、行号、多标签、查找替换、补全、快捷键。
2. **查得到**：当前实例的物品/方块、配方、标签可搜索，能插入 ID、能看配方组成、能一键生成删除代码。
3. **验得早**：保存前做语义预检；能读最近一次 KubeJS 日志并把错误定位回文件行。
4. **退得回**：每次保存/删除/恢复都有历史，能看差异、能一键恢复。
5. **AI 不添乱**：只在明确点击时调用；生成结果先看 diff，再决定是否应用。

### 非目标

- 不做通用 IDE：不做 LSP、TypeScript 类型、ProbeJS 替代品；深度编辑仍推荐 VSCode。
- 不做脚本执行器：不在启动器里模拟 KubeJS/Rhino 运行脚本；预检是静态分析，不承诺 100% 等同于游戏内结果。
- 不自动保存、不自动启动游戏、不自动调用 AI。
- 不做完整资源浏览器/3D 预览；最多做物品图标和只读资源预览。
- 本轮不改模组筛选、服务端包、实例启动逻辑。

布局原则：

- **左侧**：真实目录树（保留 `craft custom/` 层级），文件过滤、新建、重命名、删除、打开目录；底部“模板 / 历史”。

- **右侧**：`知识`（搜索/详情/插入）、`释意`（本地 + AI，点击定位）、`问题`（语法 + 语义 + 日志）三个页签。
- 左右栏可拖拽调宽，宽度记住；窄窗口下右侧变为抽屉。
- 释意从嵌套弹窗改为右侧面板，避免“弹窗里再弹窗”。

## 4. 能力设计

### 4.1 编辑器与文件

**编辑器**

- CodeMirror 6（不使用 Monaco）：
  - JS/JSON 语法高亮、行号、括号匹配、自动缩进、引号/括号自动闭合。
  - 查找替换（Ctrl+F / Ctrl+H）、跳行（Ctrl+G）、多光标可选。
  - 保存（Ctrl+S）、保存全部（Ctrl+Shift+S）、关闭标签（Ctrl+W）、切标签（Ctrl+Tab）。
  - 语法错误实时标红；语义问题来自“问题”面板。
  - 大文件保护：超过 512 KB 关闭语义检查，超过 2 MB 只读/拒绝打开。
  - 打开全屏弹窗后主动 `requestMeasure`，避免 CodeMirror 在缩放/动画容器里光标错位。
- 多标签：
  - 文件树点击打开/复用标签；脏标记、关闭确认、关闭其他、恢复上次打开的标签和光标。
  - 切换文件不再直接丢弃未保存内容。
- 外部修改冲突：
  - 读取时记录 mtime；保存时带 `expectedModified`。
  - 如果磁盘文件被游戏/其他编辑器改过，提示“重新加载 / 仍然覆盖（会先备份）”，不静默覆盖。
- 编码与换行：
  - 读取识别 UTF-8 BOM 与 CRLF/LF，保存时保持；状态栏显示。
  - 内容未变化时跳过写入和备份，避免制造垃圾历史。

**文件操作**

- 新建文件：内联输入路径，默认 `server_scripts/`，支持文件夹；不再用 `window.prompt`。
- 重命名/移动：同一套路径校验；拒绝覆盖已有文件；重命名前备份。
- 删除：确认框显示备份位置；删除前备份。
- 打开 kubejs 目录（现有能力保留）。
- 只读资源：`assets/`、`data/` 里的 JSON/PNG 可在 P4 作为只读预览，不在本轮强求。

**历史**

- 左侧“历史”抽屉：
  - 按文件分组，显示时间、大小、来源（保存/删除/恢复）。
  - 与当前内容做 diff（CodeMirror merge 或轻量行 diff），可恢复。
  - 恢复前先备份当前版本；支持清理旧备份（保留数量/天数二选一，默认保留 50 份/文件）。
  - 修复现有备份时间戳只到秒、同一秒多次保存会互相覆盖的问题（加毫秒/随机后缀）。
- 每次保存都创建快照；保存相同内容不创建。

### 4.2 实例知识索引

这是本轮最有价值的部分：把“开游戏查 ID”搬进启动器。

**索引来源（只读）**

| 来源 | 内容 | 说明 |
| --- | --- | --- |
| 模组 jar | `data/<ns>/recipes?/**.json`、`assets/<ns>/models/item/**.json`、`assets/<ns>/lang/{zh_cn,en_us}.json`、`data/<ns>/tags/items?/**.json` | 主体；逐个 jar 读取，读完释放 |
| 客户端 jar | 原版配方/物品模型/标签（如 `miao.jar`） | 原版物品必须能查，否则 `minecraft:hopper` 会被误报 |
| `kubejs/data` | 作者自定义配方/标签 | 标记来源 `kubejs/data` |
| `startup_scripts` | `StartupEvents.registry('item'/'block', ...)` 注册的 ID | 解决 `kubejs:creative_ingot` 这类脚本物品被误报 |
| 资源索引 | 原版中文名（可选） | 读 `assets/indexes` 对应语言对象；读不到回退英文 ID |

**索引内容**

- 模组：ID、名称、版本、侧别、jar。
- 物品/方块：ID、中文名、英文名、所属模组、模型引用、是否方块。
- 配方：ID、类型、输出（ID/数量）、输入（物品/标签/数量）、来源、原始 JSON（详情展开时再读）。
- 标签：ID、类型（item/block/fluid）、成员、来源。
- 脚本动态 ID：启动脚本注册的物品/方块；脚本添加的标签成员。

**构建与缓存**

- 首次进入知识页显示“建立索引”卡片：说明只读、预计耗时、可取消；不自动悄悄扫 300 个 jar。
- 进度必须是实测：已扫描 jar / 总数、已解析配方数、已用时间；不造假百分比。
- 指纹 = 模组文件名 + 大小 + mtime + 启动脚本/数据文件 mtime + 游戏/KubeJS 版本；过期提示重建。
- 缓存放启动器数据目录：`cache/kubejs/<instanceId>/index-v1.json.gz`，不写到实例/游戏目录。
- 峰值内存控制：逐 jar 读取，不保留 AdmZip 条目；只保留紧凑投影；实测目标 < 200 MB、首次 10–20 s、缓存后 < 1 s（实现后以实测为准）。
- 坏 jar/重复条目：跳过并计数，展示“x 个 jar 无法读取”，不中断整体。

**搜索与详情**

- 右侧“知识”页签：`物品/方块`、`配方`、`标签` 三个子页；支持按模组过滤、中文/拼音/ID 搜索、最近使用。
- 分页/加载更多并显示总数，绝不静默截断。
- 点击物品：
  - 显示图标、中文名、ID、所属模组。
  - “插入 ID”到光标；复制 ID。
  - 产出配方 / 用途配方列表（P2 可先做产出，P3 补用途）。
- 点击配方：
  - 类型、输出、输入（带图标/标签）、来源。
  - 一键生成并插入：`event.remove({ id: '...' })`、`event.remove({ output: '...' })`、`event.remove({ mod: '...' })`（按模组会二次确认）。
- 点击标签：成员列表、插入标签 ID、生成 `event.add/remove` 代码。
- 图标：
  - 从物品模型解析 `textures.layer0` / 父模型链，取 16×16 PNG；懒加载、按页批量请求、磁盘缓存。
  - 解析不到（`builtin/entity`、缺失纹理、动态模型）用首字母色块，不空白。
- 索引是静态的：脚本运行时动态生成的配方不会出现在列表里；界面明确标注“静态索引，运行时脚本生成的配方可能不在其中”。

**脚本内搜索**

- 左侧搜索框切换“文件名 / 内容”：内容搜索走主进程读全部 KubeJS 文件，返回路径、行号、片段，分页；点击直接打开到行。
- 大目录（>2000 文件）仍受现有上限保护，并提示。

### 4.3 模板、补全与版本感知

**版本识别**

- 从模组 jar 识别 KubeJS 版本（如 `2001.6.5`），结合实例 MC 版本/加载器显示在状态栏。
- 版本差异：
  - 1.20.1 Forge：标签常用 `forge:`；NBT 用字符串。
  - 1.21+ NeoForge：标签常用 `c:`；物品组件替代 NBT。
  - 识别不到版本时显示“通用”，模板给保守写法并标注。
- 目录与事件对应：`server_scripts` → `ServerEvents`，`client_scripts` → `ClientEvents`，`startup_scripts` → `StartupEvents`。

**模板**

- 从 7 个扩到 15+，按“配方 / 标签 / 注册 / 客户端 / 战利品”分组，可搜索、可预览。
- 覆盖：
  - 按 id / output / input / type / mod 删除；`Item.of(...)` 输出；多行选择器。
  - 有序、无序、熔炼、高炉、烟熏、营火、切石、锻造。
  - 标签添加/移除/统一。
  - 启动注册物品/方块。
  - 客户端 tooltip / JEI 信息。
  - LootJS 战利品修改（检测未安装时提示）。
- 参数化模板：插入前可填模组 ID、输出、输入，减少手改占位符；也可以直接插入到光标处再改。
- 模板不再只能追加到文件末尾，按光标位置插入。

**补全**

- 全局 API 补全：`ServerEvents`、`ClientEvents`、`StartupEvents`、`Item`、`Ingredient`、`Utils`。
- 事件方法补全：`event.remove / shaped / shapeless / smelting / blasting / smoking / campfireCooking / stonecutting / smithing / custom`。
- 字符串内 ID 补全（索引就绪时）：
  - `event.remove({ id: '...' })` → 配方 ID。
  - `output` / 普通物品字符串 → 物品 ID + 中文名。
  - 标签参数 → 标签 ID。
- 异步补全做请求序号/防抖，过期结果丢弃；索引未建立时只有 API 补全。

### 4.4 预检

保存时仍保留现有语法检查；新增“问题”面板做静态语义检查。

| 规则 | 级别 | 说明 |
| --- | --- | --- |
| JS/JSON 语法错误 | 错误 | 现有 `vm.Script` / `JSON.parse` 保留 |
| 事件与目录不匹配 | 警告 | `client_scripts` 里写 `ServerEvents` 等 |
| 占位符未替换 | 警告 | `modid:`、`recipe_id`、`example`、`your_mod` |
| 未知物品/方块 ID | 警告/提示 | 索引里没有且命名空间是已装模组；`kubejs:` 脚本注册 ID 要合并 |
| 未知配方 ID | 提示 | 脚本动态添加的配方无法完全判断，不升级为错误 |
| 标签命名空间不符合版本 | 警告 | 1.20.1 Forge 用 `c:`、1.21 用 `forge:` 等 |
| 空选择器 `event.remove({})` | 错误 | 明确无意义 |
| 按模组整体删除 | 警告 | 范围大，提示确认 |
| 依赖未安装 | 警告 | 使用 LootJS 等但模组列表里没有 |
| `Item.of` 第一个参数不存在 | 警告 | 解析 NBT/组件前先校验物品 ID |
| 启动脚本注册 ID 冲突 | 提示 | 与 jar/数据包已有 ID 重复 |

实现方式：

- 主进程用 `acorn` 解析 AST（不只是逐行正则），识别 `event.remove` 的对象属性、`Item.of`、`event.shaped`、标签调用等。
- 解析失败时退回语法错误，不输出一堆语义误报。
- 实时：编辑器内语法即时；语义检查在停止输入 800 ms 后或保存时执行，带内容版本号，过期结果丢弃。
- 只把明确的问题标红；索引缺失/运行时生成一律用“提示”，避免作者被误报吓到。
- 问题列表支持按文件过滤、点击跳行、在编辑器内下划线；保存不被阻止（保留最终决定权）。

**释意升级**

- 现有本地释意从“逐行正则”改为 AST：
  - 覆盖 `remove({input/type/output/mod})`、多行对象、`Item.of`、`shaped/shapeless`、标签、LootJS、`console`。
  - 汇总数量（例如“删除 37 条配方”），而不是只说“删除配方”。
  - 点条目跳到行并高亮范围（类型增加 `endLine`）。
- AI 释意保留“显式点击”；支持只解释选中的片段；结果回填同一面板。
- 释意面板不再嵌套弹窗，Esc 只关闭当前右侧面板。

### 4.5 日志

- 读取（只读，不启动游戏）：
  - `logs/kubejs/*.log`（按类型分文件）与 `logs/latest.log`。
  - 只读文件末尾一段（如 512 KB）避免大日志；显示最后修改时间。
- 解析典型行：`foo.js#36: Error in 'ServerEvents.recipes': ...`，映射到文件与行；同名文件给候选。
- 面板显示：文件、行、事件、错误摘要；点击跳转；可展开原始堆栈。
- 附“复制重载指令”：`/kubejs reload server_scripts`、`/reload`（仅提示，不向游戏发送）。
- 没有日志时明确提示“启动一次游戏并进入世界后生成”，不显示空面板。
- 一键启动并自动跟踪日志放到可选阶段（P4/后续），先验证日志格式和启动链路风险。

### 4.6 AI

现有“生成到编辑器”保留，补三件事：

1. **上下文更准**：
   - 发送 KubeJS 版本、加载器、实例模组 ID/名称。
   - 从索引里按提示词挑选相关 ID（最多 ~60 个）作为白名单，减少编造。
   - 带上当前脚本、选中片段、已有诊断。
2. **修改选区 / 解释选区**：
   - 选中代码 → “改写选中”或“解释选中”；生成结果以 diff 展示。
   - diff 可逐段接受/拒绝，或整体应用/放弃；应用后仍不自动保存。
3. **结果校验**：
   - 返回的代码先在主进程做语法检查；不通过则显示错误，不直接替换。
   - 超时、空响应、JSON 解析失败都有明确提示；AI 未配置时只显示本地能力。
- 安全边界不变：只使用用户自己的 AI 配置；只在明确点击时调用；不打印 key；不把整份索引/磁盘内容发出去。

### 4.7 配方生成器（P4，可选）

- 支持常用类型：有序、无序、熔炼、高炉、烟熏、切石、锻造。
- 输出：物品选择器 + 数量；输入：物品/标签选择器；3×3 图案（有序）。
- 实时预览生成的 KubeJS 代码；插入光标处或替换选区；不直接写配方 JSON。
- 版本感知：1.20.1 用 NBT 字符串，1.21+ 用组件。
- 标签生成器：选标签、增删成员，生成 `ServerEvents.tags`。
- 从配方详情“以此为模板修改”可作为后续增强。

## 6. 技术与数据

### 依赖

- `@codemirror/*`（state/view/commands/language/lang-javascript/lang-json/search/autocomplete/lint/merge）——渲染层，体积可控，不使用 Monaco。
- `@babel/parser`（`errorRecovery`）——主进程 AST 检查；已直接加入 `dependencies`，随主进程打包。
- `adm-zip`——已有，用于只读 jar 索引。
- `pinyin-pro`——已有，用于中文名搜索。
- 不引入 SQLite、Java、Rhino、原生模块。

### 索引流水线

```text
打开 KubeJS → 读取 mods 指纹
  → 有缓存且指纹一致：加载 index-v1.json.gz
  → 否则显示“建立索引” → 逐 jar 读取 → 解析 recipe/model/lang/tag
  → 合并客户端 jar、kubejs/data、startup_scripts 动态 ID
  → 写缓存（原子写）→ 释放中间对象 → 构建内存搜索表
```

要点：

- 先读客户端 jar（原版），再读模组，再读 `kubejs/data`，最后脚本动态 ID；同 ID 后者覆盖前者并记录来源。
- 配方输入解析常见形态（`item`、`tag`、数组、`count`）；解析不了的保留原始 JSON，在详情里折叠展示。
- 索引只读；缓存写到 `<data>/cache/kubejs/...`，不碰实例目录。
- 搜索在主进程内存中做，IPC 只传当前页；渲染层不接收整份索引。
- 构建按 jar 让出事件循环；如果实测主进程卡顿，再考虑 `worker_threads`/utility process，不提前复杂化。

### IPC 草案

```text
workshop:kubejs-index-status   → { state, fingerprint, counts, builtAt, error }
workshop:kubejs-index-build    → 进度事件 / 完成 / 取消
workshop:kubejs-search         → { kind, query, modId, page, pageSize } → { items, total, page }
workshop:kubejs-recipe         → 配方详情（输入/输出/原始 JSON）
workshop:kubejs-item           → 物品详情 + 产出/用途配方
workshop:kubejs-icon           → itemId → data URL（懒加载，磁盘缓存）
workshop:kubejs-diagnostics    → { path, content } → 问题列表
workshop:kubejs-history-list   → 备份列表
workshop:kubejs-history-read   → 指定快照内容
workshop:kubejs-history-restore→ 恢复（先备份当前）
workshop:kubejs-history-clean  → 按策略清理
workshop:kubejs-rename         → { from, to }（含移动）
workshop:kubejs-log-errors     → 最近日志错误（只读）
```

保存请求增加 `expectedModified` 与 `force`；冲突返回可识别的错误码。所有新路径继续走现有 `validKubeJsPath`/`safeKubeJsPath`，并补 symlink 检查。

### 性能目标

- 首次索引以 12.4 s 探针为基线，目标 10–20 s（300+ jar），实现后记录真实数字；缓存命中 < 1 s。
- 索引内存目标 < 200 MB；构建过程逐 jar 释放。
- 搜索结果页 40 条；输入防抖 120 ms；不把 3 万条一次性塞进 DOM。
- 图标按可视区域批量取，不在索引构建时解压所有纹理。

## 7. 安全与边界

- 只写 `kubejs/`；拒绝绝对路径、盘符、`..`、越界符号链接；写前备份。
- 索引只读 jar 与 `kubejs/data`，不解压到磁盘、不执行任何脚本。
- 保存/重命名/删除/恢复都先创建快照；快照路径不能越界。
- 不自动保存、不自动启动游戏、不自动调用 AI；不读取/打印 `ai.json` 的真实 key。
- 真实 `miao` 只用于只读索引/诊断测试；所有写操作测试用独立夹具，测试后清理。
- 日志可能含本地路径，只在本机展示，不上传。
- 大文件、坏 jar、重复 zip 条目都要有上限和错误提示，不无限重试。

## 9. 风险与未决

| 风险 | 影响 | 处理 |
| --- | --- | --- |
| KubeJS 日志格式/文件位置随版本变化 | 日志面板可能读不到 | 先做夹具/真实验证；读不到就只保留“打开日志目录 + 复制重载指令” |
| 物品模型解析不完整 | 部分图标空白 | 首字母色块回退；不阻塞功能 |
| 索引首次构建慢/占内存 | 体验差 | 显式建立、真实进度、逐 jar 释放、缓存；实测后再决定 worker |
| 静态诊断误报 | 用户不信任 | 明确级别；未知配方只提示；动态 ID 合并；可忽略规则 |
| CodeMirror 在弹窗/缩放容器内测量错位 | 光标/选区偏移 | 打开、resize 后 `requestMeasure`；必要时禁用容器动画 |
| 1.21 组件/NBT 差异 | 模板生成错误 | 版本识别 + 模板过滤；识别不到时给通用写法并标注 |
| 一键启动验证链路复杂 | 可能干扰实例页/游戏进程 | 放到 P4 之后单独验证；先做只读日志，不自动杀进程 |
| 新增依赖安装/打包 | 构建失败 | 先做最小 CM6 原型验证 electron-vite 打包；必要时锁定/内置版本 |

## 10. 推荐执行顺序

1. **先做 P1**：没有多标签、查找替换和历史，右侧知识面板会继续挤在弹窗里，体验不会质变。
2. **紧接着 P2**：这是作者最能感知的价值——“不用开游戏查 ID、看配方、生成删除代码”。先只读索引，不改实例。
3. **P2 上线后观察真实使用**，再决定 P3 的诊断规则强度和是否做 P4 配方生成器。
4. **不建议先做 AI 增强**：AI 的瓶颈是上下文和错误 ID，索引完成后 AI 才有可靠的白名单。
5. **一键启动验证不放进首批**：只读日志已经能覆盖大部分“启动后看报错”，启动链路风险更高。

如果只想先要一个最小可用版本：**P1 的编辑器/历史 + P2 的索引/搜索/删除代码**，就是完整的第一批；P3/P4 可以后置。
