# 风信启动器

Windletter Launcher 0.60.4 —— 风有信，月无边。一个受 PCL2 易用体验启发的 Minecraft Java 版启动器，使用 Electron、React 与 TypeScript 构建。

界面与视觉资产均为本项目原创，包含自定义标题栏、版本卡片、悬浮任务队列、日志控制台，以及浅色/深色主题和八套主题色。主题与主题色会即时套用到按钮、开关、滑杆、侧栏与强调文字，设置页内提供实时预览，切换后立即写入本机配置。

## 当前功能

- **Ctrl+K 命令面板**：任意页面按 `Ctrl+K`（也可点标题栏搜索按钮）打开，可搜索并直达启动/实例/服务器/下载/设置/更多页面，启动实例或版本、打开实例/版本目录、启动体检、账户管理、导入整合包、日志控制台、刷新列表、切换主题和清理未使用版本。支持中文关键词、↑↓ 选择、Enter 执行、Esc 关闭和鼠标悬停；打开时自动聚焦搜索框。
- **启动器自更新**：更多页新增「启动器更新」，显示当前版本，可手动检查或按开关在启动时静默检查（只请求版本清单）。发现新版本后显示更新说明、大小和发布日期；下载进度、实时速度和剩余时间均来自实际传输，支持取消下载和断点续传。安装包必须通过大小与 SHA-256 双重校验才会执行；安装时启动器退出，NSIS 在本机静默升级并在完成后自动打开新版本。更新源只允许 HTTPS（本机开发可用 localhost），下载地址、镜像和发布页都经过协议校验；校验失败会删除下载文件。未配置更新源时不会联网。安装包未做代码签名，Windows 可能显示 SmartScreen 提示。
- **AI 更新解读**：实例内容页在最近一次内容更新后显示「更新解读」，先本地列出模组、资源包、光影包和数据包的版本变化；点击「用 AI 解读」才会读取有来源的更新日志并发送摘要（最多 24 项、8 条日志、约 12k 字符），不会上传模组文件、账户或启动脚本。AI 未启用、超时或失败时自动返回本地变更摘要；缺少更新日志会明确标注，结果只读、不会改动模组。
- **KubeJS 问题一键修复**：问题页会为事件组、事件名、event 方法拼写和未定义 event 标出「可修复」；点「一键修复」先看逐行 diff，可逐项勾选，应用后只改编辑器、不会自动保存。脚本侧错误可直接「移动到 server_scripts / client_scripts / startup_scripts」，文件路径会真正改变，有未保存修改时会先提示保存。ID 未找到、语法错误等无法确定的问题仍只提示、不猜测修改。
- **备份管理**：设置页新增统一的「备份管理」，统计世界、KubeJS 历史和内容更新备份的实际占用，可按保留策略、指定天数前或全部清理，也能从实例卡片直接打开并只看当前实例。保留策略支持世界每类份数、KubeJS 每个文件份数、内容更新每实例份数，以及三类共用的最长保留天数；世界备份的手动/加载器更新/恢复三类不再互相挤占，KubeJS 保存和内容更新后会自动清理。删除内容更新备份会同步移除对应回滚记录；删除实例会连同它的全部备份一起删除。未识别的旧备份目录会显示占用但不自动清理。
- **原版实例**：下载页的「原版（不装加载器）」现在会创建独立实例，不再是只下载一份无处启动的版本；实例页顶部提供「新建原版实例」。可以选择已安装的正式版/快照直接创建，也可以在线挑选未安装版本（正式版/快照筛选、搜索、分页和总数），缺失时先补齐原版文件；实例名称可自定义。游戏文件只下载一份，实例只隔离 mods、config、saves 等内容；创建后基础版本由实例接管，版本选择器和首页不再重复列出；删除原版实例只删实例目录，保留共享版本与运行库。原版实例同样支持启动、内容/资源预览、存档、截图、体检、迁移/克隆、服务端包和「补全文件」，只是不能安装模组或加载器。
- **多版本文件夹**：选择版本或实例的弹窗顶部可切换「当前文件夹」，列表同时列出「官方启动器文件夹」和手动添加的已有文件夹，并显示各自的版本数与实例数；也可以从面板直接添加文件夹或导入整合包。切换后只影响之后下载的版本和直接启动的原版，已有实例会继续使用创建时绑定的文件夹，列表中会用文件夹标签标出不在当前文件夹的实例。路径按 Windows 规则去重，最多保留 20 个；版本清理只作用于当前文件夹，删除实例时会清理它绑定文件夹里独占的版本。首页版本栏、实例页顶部都提供「版本文件夹」按钮，点开直接展开文件夹面板；`Ctrl+K` 搜索「版本文件夹」同样可以打开。
- **游戏时长周报**：从启动到退出按真实游戏进程时长记录，保存在本机 `playtime.json`；首页两种布局的标题区都有「本周 X」徽章，游戏运行中显示「本次 0:00」实时计时。点开周报可看本周/今天/累计、周一至周日柱状图、本周实例排行和最近游戏记录；`Ctrl+K` 搜索「游戏时长」也能打开。关闭启动器不会停止计时：游戏进程会脱离启动器继续运行，同时启动一个约 4 MB 的原生小助手，等游戏退出后记录真实结束时间，下次打开自动补进周报；启动器异常退出也由它兜底。记录从 0.36.0 开始，旧会话无法追溯。
- **整合包服务端制作**：实例卡片新增「制作服务端包」入口，参考 ServerPackCreator 的工作流：扫描实例模组并读取 Fabric/Quilt 双端标记、常见客户端模组清单和未知元数据；可按勾选生成 ZIP，自动包含双端/服务端模组、配置目录、`server.properties`、`eula.txt`、Windows/Linux 启动脚本和中文说明，默认排除客户端模组、world、日志、资源包和光影。可下载对应版本的原版 server.jar，或 Fabric/Forge/NeoForge 安装器并写入首次安装脚本；Quilt/OptiFine 会提示手动准备服务端启动器。AI 辅助按钮会把模组列表发送到已启用的 AI 服务，返回客户端排除建议供逐项确认。
- **服务端包验证**：服务端包窗口新增「验证服务端包」。先做静态检查：ZIP 路径安全、`mods`、`server.properties`、EULA、双平台启动脚本、脚本引用的 server.jar/安装器是否存在且可读、常见客户端模组、配置/说明与 Java。通过后可做一次实际启动测试：解压到临时目录，把测试副本的 EULA 设为 true、换一个空闲端口，按加载器运行 Fabric/Forge/NeoForge 安装器或直接启动原版/已安装服务端，等待日志出现 `Done (` 后发送 `stop`；随后再直接运行包内的 `start-server.bat/.sh`，验证接收者双击/执行时启动脚本本身也能起服。测试自动处理 Forge/脚本末尾的 `pause`、清理临时目录并保存完整日志。测试不会修改 ZIP、原实例或存档；会执行包内 jar 和启动脚本，因此需要先勾选「来源可信」。Quilt/OptiFine 只做静态检查。
- **整合包工坊**：实例卡片新增「整合包工坊」入口，包含模组筛选、KubeJS 工作台和一致性检查。模组页读取 Fabric/Quilt 的 environment/depends 与 Forge/NeoForge 的 mods.toml 依赖，统计仅客户端/仅服务端/双端/未知、缺失必需依赖、重复 ID、依赖了客户端模组等问题，可按问题筛选、搜索和批量勾选；勾选后可直接导出只包含这些模组的 - **中文名与常用简称搜索**：内置常用模组和整合包的中文名、常见英文缩写与 PCL 风格简称索引，例如「钠」「机械动力」「暮色」「物品管理器」「输入法」「拼音」「fapi」「ae2」「jei」「mss」「优化整合包」「atm10」。输入中文或简称时，主进程先解析成对应项目和英文查询词，再分别请求 Modrinth、CurseForge；找到项目后会按当前游戏版本与加载器校验兼容性，兼容时把原项目置顶，不兼容的变体不会硬塞（Fabric 搜「机械动力」指向 Create Fabric，Forge 搜则指向 Create；「暮色」在 Fabric 下指向非官方移植，Forge 下指向官方版）。搜索结果直接显示中文名，悬停可看英文原名。CurseForge 对未解析的中日韩搜索词不会真正过滤，而是回退成热门列表；接口层已对这种情况直接返回空，避免把 GeckoLib、JEI 等热门模组误当成中文搜索结果。一个中文短词同时匹配多个内置项目时（例如「通用」同时对应通用机械、通用拼音搜索），会把这些已知项目一起置顶，同时保留 Modrinth 标题里真正含该词的结果，而不是武断只选一个或完全不翻译。加载 `mod-aliases.json` 批量表后，中文查询会优先在本地别名表里做**名称包含搜索**，按 PCL 式加权相似度排序：完全一致 > 名称前缀 > 名称中间包含，再叠加匹配位置、名称长度和别名优先级（用户导入 > 批量表 > 内置）修正；每页 20 条，支持「加载更多」继续取后续匹配项，再从 CurseForge / Modrinth 补图标、简介和下载量，形成类似 PCL 的中文长列表；没有批量表时仍只能使用内置约 100 个词条。PCL 使用离线的 MC百科翻译快照；为避免抓取 MC百科搜索页，风信在「设置 → 下载设置 → 中文搜索别名」中支持粘贴 MC百科 class 模组页链接（如 `https://www.mcmod.cn/class/3358.html`），只读取该页面并保存中文名、英文查询词和 CurseForge / Modrinth 链接，不批量扫描、不请求搜索页。内置索引和导入的别名都保存在本地，未收录的模组仍可用英文原名或 slug 搜索。

## 整合包与实例

在「实例」页可以：

- 导入本地 `.mrpack` 文件（Modrinth 整合包格式）；
- 搜索 Modrinth 整合包并安装最新稳定版本；
- 为每个实例单独启动、打开目录或删除；
- 在首页的「我的整合包」和版本选择器中切换实例。

实例目录位于 `<数据目录>\instances\<id>\`，其中 `minecraft/` 是该实例的游戏目录。原版文件、运行库、资源与 Java 运行时继续共享全局游戏目录，避免重复下载。

Forge 整合包会自动读取 `modrinth.index.json` 里的 Forge 版本并调用官方 installer 完成安装。安装期间会备份原版客户端 jar，结束后恢复，再把打过补丁的 jar 放进 `versions\<mc>-forge-<版本>\`；因此同一个原版版本可以同时保留原版和 Forge 两种启动配置。

NeoForge 使用 `neoforged.forgecdn.net` 镜像下载安装器，并在运行前把安装器内嵌的官方 Maven 地址改写到该镜像；1.20.1 的 legacy 配置会落成 `versions\<mc>-neoforge-<版本>\`，1.20.2 之后使用 `versions\neoforge-<版本>\`。原版 jar 不复制、不改写，NeoForge 通过独立的 client jar 库加载。

安装版默认把数据目录放在安装目录旁边：`<安装目录>\..\WindletterData`。例如安装在 `D:\启动器测试\windletter-launcher` 时，数据目录是 `D:\启动器测试\WindletterData`，游戏目录是其中的 `minecraft\`。可用环境变量 `WINDLETTER_DATA_DIR` 覆盖数据目录。

当前限制：

- 支持 Fabric、Quilt、Forge、NeoForge 与 OptiFine 独立版本。
- CurseForge 共享 key 不在公开源码中；PCL2-CE 同款做法是构建时从 CI Secret 注入，公开安装包仍可被逆向提取，因此这把 key 应视为“提高门槛”而不是真正保密。需要让 key 对安装包也不可见时，应改成服务端代理。源码/本地构建未注入 key 时，设置里可以填写自己的 key 或自建 API 代理覆盖；下载设置里也能把数据源切到 MCIM 社区镜像 `mod.mcimirror.top/curseforge`，不需要 key，适合官方接口不可用时兜底。用户自己填写的 key 仍保存在本机配置中，不要分享 `config.json`。
- CurseForge 返回 `downloadUrl: null` 时只打开项目页面并提供手动导入，不做 CDN 地址拼接绕过；整合包中有文件被限制分发时会停止并提示对应页面。
- Forge 使用官方 installer 静默安装：安装前备份原版 jar，安装后恢复，并把打过补丁的客户端 jar 放到独立的 Forge 版本目录，避免影响原版启动。
- Forge / NeoForge 安装器需要对应版本的 Java；Mojang 已不再提供 Java 8 运行时，1.16.5 及更早的 Forge 整合包需要系统已安装 Java 8。OptiFine 安装器本身允许使用较新的 Java，游戏启动仍按该 Minecraft 版本要求的 Java 版本准备。
- OptiFine 只跟进到官方已发布的构建；有正式版时只列正式版，只有测试版的版本（如 26.2）列出官网当前展示的最新三个预览构建并标注日期与「不兼容 Forge」；列表为空（如 26.3）表示官方连预览都未发布，而不是下载失败。独立 OptiFine 版本不含 Forge，若要同时使用 Forge 模组，需要先安装 Forge 并把 OptiFine 作为模组放入 `mods`。
- 存档备份是未压缩的完整目录副本，按文件逐个复制，因此大型世界会占用接近原世界大小的磁盘空间；备份位于实例目录内，删除实例会连同备份一起删除。当前不会自动备份模组、配置或资源包，只处理 `saves` 下的世界。
- NeoForge 官方 Maven 在部分网络不可达，风信默认使用 forgecdn 镜像并改写安装器内的下载地址。
- Quilt 加载器当前版本（0.20.0-beta.9）最高支持 Java 21，因此 Minecraft 26.x 的 Quilt 整合包会在导入时被阻止；Fabric 不受影响。
- 删除实例只会删除实例目录；若某个加载器配置不再被其他实例使用，也会一并清理。共享的原版文件与运行库不会删除。

## 下载与缓存

- 所有声明了 SHA1 的文件都会进入 `cache/objects`；再次安装相同文件时优先硬链接复用，跨卷时退化为复制。
- 下载中断或取消会保留 `.part` 与 `.part.json`，下次从断点继续；服务器忽略 `Range` 时会自动从头重下并重新校验。
- 单个域名最多 16 个并发，全局并发仍由设置中的下载并发数控制；20 秒没有收到数据会自动切换候选线路。
- 缓存目前没有容量上限与 LRU 清理，需要时可以手动删除 `cache/objects`。

## 启动器自更新

自更新需要一个 HTTPS 静态目录，放两样东西：安装包和 `latest.json`。在「更多 → 启动器更新」填写 `latest.json` 地址（或它所在目录），之后即可手动检查；打开「启动时检查更新」后每次启动会在后台请求一次版本清单，不上传账户、存档、日志或密钥。更新源未配置时不会发出请求。

`latest.json` 格式（schema 1）：

```json
{
  "schema": 1,
  "app": "windletter",
  "version": "0.60.2",
  "publishedAt": "2026-10-30T06:00:00.000Z",
  "url": "Windletter-Launcher-0.60.2-setup.exe",
  "size": 116769088,
  "sha256": "…64 位十六进制…",
  "notes": ["这一版新增了什么", "修复了什么"],
  "pageUrl": "https://example.com/releases/0.60.2",
  "mirrors": []
}
```

- `url` 可以是相对 `latest.json` 的文件名，也可以是 HTTPS 绝对地址；`mirrors` 可选，用于备用线路。
- `size` 必须与安装包一致，`sha256` 必填；安装包小于 1MB 或清单大于 512KB 会被拒绝。
- `notes` 最多 20 条，显示在更新卡片里；`pageUrl` 可选，必须是 HTTPS。
- 更新源只接受 HTTPS；仅本机测试允许 `http://localhost`、`127.0.0.1` 或 `[::1]`。
- 安装包下载到 `<数据目录>\cache\updates`，安装成功后下次检查会清理旧安装包。取消下载会保留分片，继续时按 Range 从断点续传。
- 安装使用 NSIS 的静默更新参数，保留原安装目录和 `WindletterData`；不会关闭正在运行的 Minecraft 进程，因此游戏运行中会禁用「安装并重启」。

生成清单：

```bash
npm run update:manifest -- "D:\WindletterOut\Windletter-Launcher-0.60.2-setup.exe" \
  --notes-file build/update-notes.txt \
  --out "D:\WindletterOut\latest.json"
```

脚本会读取 `package.json` 的版本号（也可 `--version` 指定）、安装包大小并计算 SHA-256，默认把安装包文件名写成相对地址；如果文件不放在同一目录，用 `--base https://…/目录/` 生成绝对地址。把安装包和 `latest.json` 一起上传即可。发布页、GitHub Release 或 OSS 都可以，只要最终能通过 HTTPS 访问清单文件。

安全边界：清单必须通过 HTTPS 获取，安装包还要满足 `size` 与 `sha256`；校验失败会删除文件，不会运行。安装程序只接受本应用下载目录中、已通过校验的 NSIS 安装包。当前没有代码签名和增量更新，完整安装包约 111MB；没有配置签名证书，Windows SmartScreen 可能提示未知发布者。

## 公开源码与构建密钥

公开源码采用 PCL2-CE 同款模型：**共享 CurseForge key 不进入仓库，只在发布构建时注入**。源码里的 `buildSecrets.ts` 读取 Vite 在构建时替换的常量；没有注入时为空。`electron.vite.config.ts` 从以下环境变量生成：

- `WINDLETTER_CURSEFORGE_API_KEY`：共享 CurseForge key；不要写进 `.env.example` 或提交到仓库。
- `WINDLETTER_DEFAULT_UPDATE_FEED`：新安装默认更新源；发布构建设置为 `https://github.com/muyi0736/windletter/releases/latest/download/latest.json`。

本地发布构建示例（PowerShell）：

```powershell
$env:WINDLETTER_CURSEFORGE_API_KEY = "你的 key"
$env:WINDLETTER_DEFAULT_UPDATE_FEED = "https://github.com/muyi0736/windletter/releases/latest/download/latest.json"
npm run build
```

GitHub 发布：0.60.3 先由本地构建后通过 API 上传；0.60.4 起已启用 `.github/workflows/release.yml`，在仓库 Secret 配置 `CURSEFORGE_API_KEY` 后，推送 `v*` 标签会自动完成类型检查、NSIS 打包、绝对地址 `latest.json` 生成和 GitHub Release。工作流只在 tag 上运行，普通 PR 不读取 Secret。当前 `.env*`、本地密钥文件和安装包输出均已加入 `.gitignore`。

安全边界必须说清楚：注入后的 key 仍在主进程 bundle 和公开安装包里，任何人拿到安装包都可以逆向提取；源码干净不等于 key 不可提取。需要真正保护 key 时，只能改成服务端 CurseForge 代理。当前 0.60.2/0.60.3 安装包已经包含旧 key，公开源码/公开发布前应轮换；如果希望继续 PCL2-CE 模式，就接受“源码不含 key、公开二进制可提取”的边界。

## MC百科本地别名表脚本

`scripts/mcmod-alias-import` 可以把 MC百科 class 模组页转换成风信可加载的 `mod-aliases.json`：

```bash
npm run aliases:mcmod -- 840 3358
npm run aliases:mcmod -- --input classes.txt --data-dir "D:\启动器测试\WindletterData"
npm run aliases:mcmod -- --html-dir ".\saved-mcmod-pages"

# 本机已有 PCL 的离线翻译快照时，只在本机个人使用，勿随安装包分发
npm run aliases:mcmod -- --pcl-buf "C:\PCL\mcmod.buf" --data-dir "D:\启动器测试\WindletterData"
```

支持数字 class ID、完整链接、URL 列表文件和本地保存的 HTML；默认合并已有条目，联网请求默认间隔 700ms。脚本只读取 class 页面，不请求 MC百科搜索页、不遍历站内页面。风信启动时会加载数据目录下的 `mod-aliases.json`（最多 30000 条），与设置中导入的 `search-aliases.json`、内置词表一起合并；界面里只管理后者。详细参数和输出格式见 [scripts/mcmod-alias-import/README.md](scripts/mcmod-alias-import/README.md)。

MC百科内容按 BY-NC-SA 3.0 使用；请只转换自己需要的页面，并遵守站点条款。`--pcl-buf` 读取的是你自己本机 PCL 资源里的离线翻译快照，生成结果仅供本地个人使用，不要随安装包、源码仓库或公开镜像分发。
